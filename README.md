# Danalytica Blog — Setup & Publishing Guide

Zero build tools. No Node. No Ruby. Just files and GitHub Pages.

---

## Repo Structure (after setup)

```
your-repo/
├── index.html              ← your existing homepage (untouched)
├── logo.svg
├── logo-small.svg
├── favicon.svg
├── CNAME
│
├── blog/
│   ├── index.html          ← blog listing page
│   ├── post.html           ← individual post shell (shared by all posts)
│   └── feed.xml            ← RSS feed (regenerated by generate_feed.py)
│
├── posts/                  ← your Markdown files live here
│   ├── building-rag-systems-that-actually-work.md
│   ├── real-time-ml-pipelines-kafka.md
│   └── llm-finetuning-guide-startups.md
│
├── generate_feed.py        ← run before pushing to update RSS
└── new_post.py             ← scaffold a new post
```

## One-Time Setup

1. **Copy these files into your existing repo:**
   - `blog/` folder (index.html, post.html, feed.xml)
   - `posts/` folder (the sample .md files)
   - `generate_feed.py`
   - `new_post.py`

2. **Add "Blog" to your homepage nav** — in `index.html`, find the nav-links ul and add:
   ```html
   <li><a href="/blog/">Blog</a></li>
   ```

3. **Push to GitHub.** GitHub Pages serves everything statically — no configuration needed.

4. **Test:**
   - `https://danalytica.com/blog/` → listing page
   - `https://danalytica.com/blog/post.html?` → auto-loads based on URL
   - `https://danalytica.com/blog/feed.xml` → RSS feed

> **How post.html works:** All posts share the single `blog/post.html` file.
> Each Markdown file lives in `/posts/`. The post.html page reads its own URL,
> extracts the slug (e.g. `building-rag-systems-that-actually-work`), then
> fetches `/posts/building-rag-systems-that-actually-work.md` and renders it.
> No per-post HTML files needed.

## Writing a New Post

### Step 1 — Scaffold it
```bash
python new_post.py "How We Built a Data Lake for Healthcare"
```
This creates `posts/how-we-built-a-data-lake-for-healthcare.md`.

### Step 2 — Write it
Open the file and write Markdown. Standard syntax works:

```markdown
---
title: How We Built a Data Lake for Healthcare
date: 2025-06-15
category: Data Engineering
tags: [Snowflake, dbt, HealthTech]
excerpt: One sentence for the listing page and RSS feed.
readTime: 6 min
author: Danalytica Team
---

Your content here...

## Section One
...

## Conclusion
...
```

### Step 3 — Register the post

Add an entry to the `POSTS` array in **both** of these files:
- `blog/index.html` (the listing page)
- `blog/post.html` (the individual post page — for prev/next navigation)

```javascript
{
  slug: "how-we-built-a-data-lake-for-healthcare",
  title: "How We Built a Data Lake for Healthcare",
  date: "2025-06-15",
  category: "Data Engineering",
  tags: ["Snowflake", "dbt", "HealthTech"],
  excerpt: "Your excerpt here.",
  emoji: "🏥",
  featured: false,   // set true to make it the hero card
  readTime: "6 min"
},
```

### Step 4 — Regenerate the RSS feed
```bash
python generate_feed.py
```

### Step 5 — Publish
```bash
git add .
git commit -m "Add post: How We Built a Data Lake for Healthcare"
git push
```

That's it. The post is live at:
`https://danalytica.com/blog/post.html` (GitHub Pages serves it via the slug in the URL)

Wait — actually posts are linked as:
`https://danalytica.com/blog/posts/how-we-built-a-data-lake-for-healthcare.html`

The blog listing links there. post.html uses JavaScript to read the URL path and fetch the right `.md` file. This works on GitHub Pages because the file being fetched (`/posts/slug.md`) is a real file.

## Cross-Posting to Medium / Dev.to

Both platforms support RSS auto-import.

### Medium
1. Go to medium.com → your profile → **Settings → Import a story**
2. Or use RSS auto-import: medium.com/p/import → paste `https://danalytica.com/blog/feed.xml`

### Dev.to
1. Go to dev.to → Settings → **Extensions → RSS Feed**
2. Paste: `https://danalytica.com/blog/feed.xml`
3. Dev.to will check your feed periodically and create drafts from new posts

## Updating the RSS Feed

The RSS feed is a **static file** that you regenerate manually before each push. This is intentional — no CI/CD complexity.

```bash
python generate_feed.py   # reads all posts/*.md, writes blog/feed.xml
git add blog/feed.xml
git commit -m "Update RSS feed"
git push
```

## Troubleshooting

**Posts not showing on listing page:**
- Make sure the `slug` in POSTS exactly matches the `.md` filename (without extension)

**Post page shows "Couldn't load post":**
- The `.md` file must be in `/posts/` at the repo root
- File name must be exactly `slug.md`
- GitHub Pages serves from the repo root, so the fetch path `/posts/slug.md` resolves correctly

**RSS not updating on Medium/Dev.to:**
- Both platforms cache feeds. Medium checks ~daily. Dev.to has a manual "fetch now" button in settings.

**Fonts not loading:**
- Fonts come from Google Fonts. Works on live site. May not work when opening `file://` locally — test via `python -m http.server 8000` and visiting `localhost:8000`.
